# Security

This repository builds and operates <https://jon-allyn.com>. It is published so
the engineering behind that site can be read, which means the security of the
running system does not depend on anything here being secret.

## Reporting a vulnerability

Use GitHub's **private vulnerability reporting** on this repository:
*Security* → *Report a vulnerability*. That opens a channel only you and the
maintainer can see.

Please do not open a public issue for anything exploitable.

**There is no security@ address, and that is deliberate.** The `jon-allyn.com`
domain publishes a null MX record (RFC 7505) and `v=spf1 -all` — it sends and
receives no mail by design, so any address at that domain would bounce. See
`terraform/dns.tf`.

Expect an acknowledgement within a few days. This is one person's personal
project, not a funded programme, and there is no bounty.

## In scope

- This repository's Terraform, Lambda handlers, and GitHub Actions workflows
- The live site and its `/api/*` endpoints
- The DNS configuration for `jon-allyn.com`

## Out of scope

- Missing content on the site, or the `TODO:` markers in the site repository —
  those are tracked as OQ-1 in `specs/001-personal-site/spec.md`
- Findings that depend on already holding credentials for the AWS account
- Volumetric denial of service. The site is a personal portfolio behind
  CloudFront with a budget alarm; absorbing a flood is not a design goal
- Reports generated by running a scanner against the live site without asking

## Design decisions that are intentional, not findings

Before reporting, note that these are deliberate and documented in
`specs/001-personal-site/plan.md`:

| Observation | Why it is that way |
| --- | --- |
| The Terraform role has broad IAM permissions | plan §4.8 — the controls are the trust policy, the apply gate and the budget alarm, not an allowlist that ends at `*` anyway |
| The Lambda Function URL is publicly resolvable | plan §4.1 — it uses `AWS_IAM` auth and returns 403 to anyone but CloudFront's OAC. A resolvable hostname is not an open endpoint |
| The hosted zone is a data source, not a managed resource | plan §4.4 — so `terraform destroy` cannot delete the domain's DNS |
| Checkov reports suppressed findings | `.checkov.yaml` — 26 suppressions, each with a written reason |
| The AWS account id may appear in older workflow logs | Masked going forward by `scripts/resolve-config.sh`; logs predating that change were purged before this repository was made public |

If you think one of those decisions is wrong, that is a worthwhile issue rather
than a vulnerability report — open it publicly and make the argument.

## What this project guarantees

These are invariants, and a break in any of them is a real finding:

1. No static AWS credentials exist in either repository. Authentication is
   GitHub OIDC only.
2. The S3 bucket and the Lambda Function URL are reachable only through
   CloudFront.
3. The domain sends no mail, and publishes records saying so.
4. Every deploy is verified against the live site before the run is called
   successful.
